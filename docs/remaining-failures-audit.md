## 202309B 的新精度反例

[洛谷题面](https://www.luogu.com.cn/problem/P16055) 允许实数角度；坐标绝对值不超过 `10^6`，单次缩放系数 `[0.5,2]`，任意操作区间的缩放乘积 `[0.001,1000]`，答案按绝对误差 `0.1` 判定。

此前将角度取整到千分位的实现会在单次旋转 `0.0001`、点 `(1000000,0)` 上把应当约为 100 的纵坐标算成 0。`b2f4624` 已正确修复了这个历史错误。

但在 Apple Silicon / Apple Clang 21 上，`long double` 与 `double` 都只有 53 位有效二进制位。若每个补偿求和前缀最终只保留一个浮点数，两份大前缀相减时仍可能丢失低位；最大坐标与最大缩放会进一步放大误差。本次用 70 位 Decimal 前缀及独立 Taylor 三角函数，复核了以下严格合法的构造：

- `n=100000,m=1`；前 99990 个操作全为 `2 6.283`，随后九个 `1 2`，最后一个 `1 1.953125`。
- 查询为 `2640 100000 1000000 -1000000`。
- 每个缩放系数合法，任意区间缩放乘积均在 `[1,1000]` 内；总缩放 1000 是精确二进制值，不产生缩放舍入误差。
- 参考结果为 `(1413795406.86997506495..., 34388188.573428274159...)`。
- 旧单值前缀版本最大绝对误差 **0.1759131466**，超出 0.1；修复版误差 **0.0498755043**，符合要求。

另一个固定种子的长随机角度构造有 5003 个查询，旧版最大误差 **0.1424731205**，修复版 **0.0002193396**。旧版最坏查询的输入转换角度误差约 `1.36e-14`，而前缀相减误差约 `-1.02e-10`，因此主要问题是前缀低位损失。

旧洛谷 AC 仍然是真实的历史结果：其评测环境可能使用精度更高的 `long double`，且数据未必覆盖这个边界。新旧代码的验证记录已区分。

## 修复与可复核证据

[当前源码](../202309/B.cpp) 用 Neumaier 求和保存每个前缀的高、低两部分；查询时补偿相减，再用角度和公式分别计算高低部分的正弦和余弦。它避免提前把低位重新舍入掉，也避免用近似 `2π` 手工对大角度取模。总时间仍为 `O(n+m)`，空间 `O(n)`。

新版于 2026-10-25 在[曙梦 OJ 正式复验](https://oj.shumeng.tech/record/6addb80574ace1cba9a20d52)取得 **100 分 Accepted**，峰值 **341 ms / 11.1 MiB**。提交源码 SHA256：`6a128e8d781e9fde0cb77ad2fa22862e21d8b03b9afeb979f5fad8c2c84f0bfc`；此前洛谷版本 Git blob：`20776d0627c78f6c02502fc311a5648a5f01a3cb`。

[便携精度回归入口](../tests/precision_regressions.py) 使用 Python 3.9 标准库，编译当前工程源码到 `.build/precision-regressions`：

```sh
python3 tests/precision_regressions.py
python3 tests/precision_regressions.py --stress
```

默认执行 2 个保存样例、500 组独立逐次操作对拍及上述确定性高精度反例。`--stress` 追加 5003 个长随机角度查询、6 种重复边界角度和最大查询数测试；不依赖旧版二进制或机器上的临时目录。[验证报告](../tests/precision-report.json) 保留机器、编译器、源码哈希、历史误差、最新运行结果和正式评测链接。
